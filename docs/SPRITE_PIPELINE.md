# Sprite row pipeline

`rabbitpunch_sprite_row.vhd` wraps the unchanged JTFRAME drawer for one row of
a native 16x32 Rabbit Punch sprite. New logic is VHDL with unsigned ports.
The reference is MAME 0.289 `src/mame/vsystem/rpunch.cpp`, `splayout` and
`draw_sprites`, pinned in HARDWARE_NOTES.md.

The producer waits for `o_row_ready`, supplies sprite code, local row, destination
X/Y, palette, flips and the behind-foreground tag, then asserts `i_row_valid`
for the accepting edge. Metadata is latched. The adapter pulses the drawer's
start input and issues one external ROM request at a time. Its request is a
single-cycle pulse; a future shared transport must retain it until serviced.
There is no ROM response backpressure, and every accepted request must receive
exactly one response even if the adapter is reset.

The donor draws 16-high cells, so the adapter appends the vertically adjusted
fifth row bit to the 11-bit sprite code. It maps donor `{code12,half,row4}`
addresses into packed-ROM `{code11,row5,half}` word addresses. ROM words are
little-endian: the lowest-address byte is in bits 7..0. MAME's sprite layout
reverses byte pairs within each group of four pixels; the adapter converts
those packed pixels into the four bitplanes consumed by JTFRAME.

The second eight-pixel ROM word is requested while the first half is drawing.
Outputs comprise two eight-pixel bursts with a possible wait between them.
There is no output backpressure; the consumer must accept each asserted pixel.
Coordinates wrap at 512. Palette indices cover 768..1023, pen 15 is transparent,
and the priority tag accompanies every pixel. This adapter does not decide which
sprite wins an overlap or whether a foreground tile hides a sprite.

Reset suppresses output immediately, drops the partial row and drains any
outstanding ROM reply before accepting a fresh row. There is no line RAM or
frame RAM here. Physical raster, descriptor latching, candidate scheduling,
shared SDRAM arbitration, sprite occupancy and final mixing remain open.
In particular, a successful row test does not prove a whole scanline deadline.

## Verification

`sim/video/sprite_row_tb.vhd` drives rows generated by `run_sprite_tests.py`.
The bench supplies graphics ROM data and checks every emitted pixel against
an independent direct sampler of the MAME layout. It verifies both ROM word
addresses, exactly two requests and sixteen pixels per completed row, and
that the second request occurs before all first-half pixels have been emitted.

The synthetic set checks 30720 rows / 491520 pixels: five code boundaries,
all 32 rows, all sixteen palette groups, both flip directions independently,
0/3/11 additional ROM wait cycles, X wrapping and changing inputs while busy.
Fresh rows after resets are checked separately. Reset cases interrupt the
first ROM wait, active drawing, the second ROM wait and the pre-request phase.

Each of the six real MAME fixtures supplies all 54 active descriptors and all
32 local rows: 1728 rows / 27648 pixels per scene, 165888 pixels total.
These exercise graphics, metadata and row addressing; they do not yet compare
sprite overlap, visible clipping or complete mixed frames. Commands come from
captured descriptors, while expected pens are sampled directly from ROM bytes.
No ROM data is committed. Hashes and results are in reference/sprite_checks.json.

```powershell
./scripts/d_drive.ps1 scripts/run_sprite_tests.py
./scripts/d_drive.ps1 scripts/build_staged.py --synth-check sprites
```

The standalone Quartus project tests only this adapter and its JTFRAME drawer
at the 48 MHz evaluation clock, with virtual I/O. This is not a full-core fit,
a final board clock choice or a deployable RBF.

Commit 2f886cb passes that Quartus 17.0.2 fit on 5CSEBA6U23I7: 116 ALMs,
170 registers, zero M10K and zero DSP blocks. All corners pass setup, hold
and minimum pulse width; worst setup slack is +10.794 ns and worst hold
slack is +0.152 ns, with zero illegal clocks or unconstrained paths.
The adapter and donor hierarchy survive synthesis. See reference/sprites_synth.json.
